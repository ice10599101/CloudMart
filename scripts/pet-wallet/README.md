# 宠物钱包切换工具包（W04/§6、§10.3）

本目录是 LEGACY_WISH → PET_COIN 切换的运维交付物。**所有脚本以清单化、可核对为原则；
不存在任何"把社区余额复制/改写进新钱包"的脚本（§6.5-5 明令禁止）。**

## 文件清单

| 文件 | 用途 |
| ---- | ---- |
| `preflight.sql` | 只读预检：旧单未决数、退款完整性、键长度、重复主宠/配置版本、Flyway 版本核对 |
| `cutover-manifest.json` | 切换清单模板：批次号/政策版本/前置条件/统计口径/证据引用 |
| `README.md` | 本说明（切换窗口 Runbook） |

## 切换窗口 Runbook（§6.5，全部步骤需两人复核）

1. **预检**：在目标环境执行 `preflight.sql`，逐项确认——未决旧单数必须为 0
   （无法收敛的逐单人工核查并留证据，不能带着未知扣款切换）；将结果摘要哈希填入 manifest。
2. **备份**：mall_pet / mall_wish 全量备份并做恢复演练，记录 backupRef。
3. **停流量**：`pet.wallet.mode=PAUSED`（Nacos 下发），网关与服务端同时生效；
   等待在途事务结束（观察 `pet_operation` 无 PROCESSING/COMPENSATING 新增）。
4. **冻结奖励快照**：对未领取的活动/任务/合作奖励补冻结快照并标记结算币种
   （页面展示迁移说明：未领取的币奖励按相同名义数值发 PET_COIN）。
5. **建批次**：填写 `cutover-manifest.json`，逐用户生成/核验 `pet_wallet_cutover_item`
   （新期初恒 0；旧余额仅快照留档）；存在无法判断"是否已领"的记录则 BLOCKED，不猜测。
6. **切换**：`pet.wallet.mode=PET`；烟测账号执行 PET 真实购买/奖励/退款并触发一轮对账
   （管理页"立即执行一轮对账"或 `POST /admin/pet/wallet/reconciliations/run`）。
7. **开放**：全量放开；24 小时观察交易错误率/最老未决单/差异数（§6.6）。

## 回滚（§6.7，禁止回滚到混用钱包）

- 新账本未接收任何交易：回 `LEGACY` 响应兼容版本，保留新增表与切换报告。
- 新账本已有交易：**禁止**把余额覆盖回快照、删流水、把币操作重新指回 wish；
  只能暂停新收支（`PAUSED`），按原单逐笔冲正/退款。

（删除前保留历史查询与脱敏审计）。
