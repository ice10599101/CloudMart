## 2. 端到端覆盖明细（e08，56 项全绿）

- **A04** 磁力/种子/网盘三类来源保存、resolve 返回 magnet/https、非法磁力拒绝
- **A07** 提交→撤回→重提 submitSeq 递增；旧批次(submitSeq 过期)决策 409
  `SOFTWARE_SUBMIT_STALE`
- **A11** 跨软件 ID 攻击（resolve/点赞/回复）全部拒绝且不泄露存在性
- **A14** 审核详情双快照对比（待审 vs 线上），来源标签变化可辨
- **A17** 30 并发收藏/点赞幂等：计数=关系行数
- **A19** 反馈同人同指纹去重；标记 RESOLVED 后可再次反馈（V8 唯一键修复后验证）
- **A24** 并发评分一致性；撤销无残留
- **A26** 作者下架后榜单**实时**剔除（穿透 10min 缓存）、重新上架回榜
- **A38** 人工授权→resolve 200→撤销→403（撤销按 userId 幂等）
- **A41/A43** 查看条件变更经审核生效；ADMIN_PAID 未授权 403；联系入口展示/停用
- **A42** 游客视角全链无真实链接/提取码泄露
- **A48** 内部擦除与管理面直连 9026 均要求服务令牌（scope 边界）
- **A51** 举报处置→BAN_SOFTWARE→公开面即时隐藏→解除→作者重新上架闭环
- **功能开关（A30）** resolve/榜单/订阅三类开关关闭均 403+对应
  `SOFTWARE_*_DISABLED`；总开关关闭时公共读写 403、作者受控入口与后台处置保留；
  脚本退出自动还原 Nacos 配置

## 3. 过程中发现并修复的缺陷（真问题清单）

| # | 缺陷 | 级别 | 修复 |
|---|---|---|---|
| 1 | 审核通过后 working_revision_id 未清空（MP NOT_NULL 策略跳过 null 列）→ 已发布软件无法再编辑 | P0 | approve 改显式 LambdaUpdateWrapper（2082eeb1） |
| 2 | 快照 12 个可空字段"清空"静默失效（同类根因）→ 切回 REGISTERED 残留联系入口 → DB CHECK 500 | P0 | 字段级 `FieldStrategy.ALWAYS`（75485c99） |
| 3 | 榜单接口 500：record 构造器自动映射要求每参数有匹配列 | P0 | 改有序 ID 查询（2082eeb1） |
| 4 | 反馈唯一键覆盖全部状态 → RESOLVED 后重反馈 500（A19） | P1 | V8 迁移：status 纳入唯一键 |
| 5 | resolve-enabled 开关完全未实现（A30 无法验收） | P1 | resolve 入口服务端校验 |
| 6 | 授权列表缺 grantId（撤销定位键缺失） | P1 | 行构造补 grantId |
| 7 | 功能开关体系缺失（总开关只挡调度器；P1 无独立开关） | P1 | 拦截器+三个新开关 |
| 8 | Prometheus 抓取被 SecurityConfig 拦截（指标 job 全部静默失败） | P1 | 放行 /actuator/prometheus |
| 9 | 业务指标缺失（审核积压/反馈积压/Outbox 死信/广播延迟/resolve 拒绝） | P2 | SoftwareMetrics 5 gauge + counter/timer |

修复回归：单测全绿 + IT 全绿 + e08 全绿三重复验。

## 4. 压测报告（缩比口径，如实记录）

**口径**：5000 软件（ACTIVE+已审快照）/ 20000 评论 / **50 并发** × 25s/场景；
客户端与本机网络（公网到部署服务器，含 RTT）；限流压测窗口内临时关闭。
手册全量目标（1 万软件/10 万评论/100 并发）**未执行**，本结果为缩比推算依据。

| 场景 | RPS | p50 | p95 | p99 | 错误率 |
|---|---|---|---|---|---|
| 列表 /api/software?size=20 | 28~235* | 139~603ms | **528~3590ms** | ~1s~8s | 0 |
| 详情 /api/software/1 | 155~189 | ~112ms | ~560ms | ~1s | 0 |
| 评论分页 size=20 | 203~256 | 83~160ms | **378~543ms** | ~0.6~1.2s | 0 |
| 榜单（缓存命中） | 144~179 | ~93ms | ~693ms | ~1.3s | 0 |
| 获取链接 resolve（认证） | 177 | ~220ms | ~604ms | ~0.9s | 0 |

\* 列表场景跨轮波动大（28~235 RPS）。EXPLAIN 证实查询计划本身最优
（反序主键扫描 + Limit，cost=277）；波动源于**默认排序（featured_rank,
last_release_at, id）无可覆盖索引 → 5000 行 JOIN 结果 filesort**，在共享
服务器（20+ 容器同机）CPU 争用下放大。

**结论与建议**：
- 评论分页满足 p95 ≤ 800ms 目标（378~543ms）；列表 p95 在争用窗口超 500ms 目标
- 上线 1 万软件规模前建议：`ALTER TABLE software ADD idx_feat_rel
  (featured_rank, last_release_at)`（或默认排序改 id DESC），可消除 filesort
- 全量目标规模（1 万软件/10 万评论/100 并发）压测**待执行**，需独立压测环境
