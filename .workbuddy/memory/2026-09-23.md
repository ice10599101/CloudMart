## v6：3D「不生动」的实测诊断 + 角色层整体删除

**用户反馈**：「这个宠物模块是 3D 的，看上去感觉不生动」+「原来这只猫宠物删掉，宠物也要重新做」。

### 诊断（全部有据，先查再改）
1. **场景里一盏灯都没有** —— `PetHome.scene` 只有 Canvas / UICamera / Main3DCamera / Root，
   无任何 `cc.DirectionalLight`；`cc.ShadowsInfo._enabled = false`。
2. **房间与角色共用同一套「写死的光」** —— 都用自研 `pet-toon`，
   而 `lightDir / fillDir / lightCtrl / shadeCtrl` 是**固定常数**。
   → 物体之间没有光的关系（不投影、不遮挡、窗光不落地），读作"一堆贴纸叠在一起"。
3. **主光几乎垂直向上** —— 旧 `lightDir.y = 0.74`，配合半兰伯特 `dot*0.5+0.5`，
   地板 ndl 0.87（lit 1.0）与正对镜头的墙 ndl 0.76（lit 0.96）**几乎同样亮**，
   而墙/地/毯/猫全在一条 3% 宽的明度带里 → 塑料感主因。
4. **地毯顶面在 y≈0.045~0.07**（逐层圆盘），我第一版把接触阴影放在 y=0.009 → 全被盖住。

### 已落地改造（pet-toon + PetRoomBuilder + 机位）
- `lightDir` → **来自窗户** `(-0.46, 0.56, -0.69)`：地板全亮、正对镜头的墙落暗 → 出现明度阶梯

  抹掉暗部锚点，落到 0.14 才有 35% 分离）
- `shadeColor` 冷紫灰 `(0.70,0.66,0.72)` → **暖灰棕** `(0.62,0.54,0.47)`；`rimColor` 转暖

### 绑骨（`rig_cat.py`）—— 三个关键发现
1. **Blender 自动权重（骨热）彻底失败**：`Bone Heat Weighting: failed to find solution`，
   14 个骨骼组全 0 顶点。原因是**这个网格根本不是融合整体** ——
   实测 **970 个连通分量、最大岛只有 359 个顶点**（图生 3D 的碎片化拓扑）。
   骨热需要连通性，必然失败；又不能 remesh（会毁掉烘焙的 UV 与三张贴图）。
2. **撕裂的真正成因不是过渡不平滑，是碎片分家**。我一度给"附件小岛"做整岛刚性绑定，
   结果整套权重变成"每块碎片各自一个权重"，一动就互相拉开 —— 看到的裂缝就是这个。
   **正解：逐点权重 + 邻接平滑，但邻接必须按空间距离建（不能按共享边）**，
   否则平滑跨不过碎片缝。`NEIGH_CELL=0.022 / NEIGH_RADIUS=0.032`。
   换完之后前倾低头的颈胸过渡立刻干净。
3. **纯距离场分不开"相邻但不同部位"**（围巾就贴在颈线下面）。必须加**用实测解剖高度做的门控**：
   `GATE['Head']=('above',0.360,0.455)`、耳 `('above',0.735,0.800)`。
   门控带宽要留足（0.07~0.10），窄了会在交界处留硬边。
   另加显式**空间锁**（胡须/口鼻 `z>0.46 and y<-0.17` → Head 100%）+ **区域生长**：
   胡须是细长条必然跨出任何固定框，只锁一半会被硬生生拉长。

### 明确放弃的事（都写进了脚本注释，不是忘了）
- **尾巴不绑**：它紧贴人身（实测 x≈-0.33~-0.37，而人体最大半宽就是 0.32，几何上几乎相交），
  任何距离权重都会把身体一起拽走（Tail1 抓走 1463 顶点）。坏掉的尾巴比静止的尾巴糟。
  要摆动只能从资产侧解决：让尾巴与身体留真实间隙，或改用测地距离/网格分割。
- **不做眨眼**：眼睛是烘焙进反照率贴图的，没有独立眼皮几何。要做必须先反查眼球 3D 位置再补两块眼皮。
- **不做行走循环**：碎片化网格上做不了可靠的四肢形变。

### 未收口：宠物材质（**这一轮卡在这里**）
**现象**：猫进场景了、位置比例对、动画在跑，但渲染成**单色**（无贴图、无眼睛/围巾颜色）。

诊断链（逐一排除，全部有据）：
1. 不是层/可见性：网格与灯都在 `layer=1073741824`(DEFAULT)，灯的 visibility 掩码含该位 ✓
2. 不是材质类型：glTF 材质是 `doubleSided: true` + `alphaMode` 缺省(OPAQUE) ✓

4. 不是 UV 缺失：加诊断开关把 `v_uv` 直接画成红绿 → 猫身上出现紫/青/粉色块，**UV 有真实数据** ✓

`mainTexture`（`editor.type: texture`）+ `mapCtrl.x` 开关 + frag 里 `base *= texture(mainTexture, v_uv).rgb`。
**结果：体积和描边出来了（比 builtin-standard 明显好），但贴图仍没上。**

**关键线索（下一步的突破口）**：渲染出来的暗部是**暖灰**、描边可见 ——
这正是 pet-toon 的**默认值**（`shadeColor` 默认 (0.62,0.54,0.47)、`outlineCtrl` 默认 0.006）。
→ 说明**整组 `setProperty` 都没生效**，不只是贴图。

把材质赋给 `SkinnedMeshRenderer.material` 是否被引擎替换/克隆（考虑改用
`setMaterial(mat, 0)` 或在 `materials` 数组上赋值），以及 pass 属性表用的是 YAML 锚点
`*props` 时运行时 setProperty 的寻址是否正常。

### ② 眼皮 + Blink —— 成功
- **做法**：用最小二乘拟合**眼球球心与半径**（在双眼中心 0.085 邻域取顶点，解代数方程
  `|p-c|²=r²`）→ 实测左眼 中心 (-0.115,-0.279,0.610) r=0.0746 / 右眼 (0.149,-0.282,0.609) r=0.0771。
  再生成**同心球冠**（半径 ×1.05、张角 58°、161 顶点/160 面）作为眼睑。
  贴图坐标取"眼球正上方那个顶点"的 uv —— 眼睑自动就是周围毛色，不会比身上浅一块。
- **⚠️ 眼皮骨的朝向决定旋转轴**：第一版把骨头朝上（+Z），`rotation_euler.x` 变成绕局部 X 转，
  眼皮直接甩到头的侧面去了。改成骨头**沿 +X（左右轴）**、用 `rotation_euler.y` 扭转，

- **⚠️ 眼睑必须排除出身体权重**：否则"半径全不覆盖时兜底给最近骨骼"会把眼周脸面顶点分给眼皮

  它们不会被导出 —— 骨骼与动画都在、网格却缺了，GLB 上眼睛会永远睁着。

## ③′ 尾巴：用户拍板「正常做贴在屁股后面能摆动的」—— 换个思路反而成了

用户提出：别硬掰那条绕身尾巴，**正常做一条贴在屁股后面、能摇晃摆动的**。

这个思路是对的，也是这个资产上**唯一可行**的做法：
**旧尾巴不动它去分离（一推就撕），而是整块删掉，在屁股后面重新长一条** ——
新尾巴与身体有真实间隙，完全在我控制之下，权重可以按路径参数**解析计算**，不依赖距离场。

### 做法（`rebuild_tail()`）
1. 复用已验证的"旧尾巴中心线拟合"定位旧尾巴
2. **逐顶点按管道删除**旧尾巴（管径取"贴线中位"0.0458 × 系数 0.075）
3. 沿新路径扫出**锥形管**（6 点路径 → 5 节骨骼，半径 0.058→0.018 递缩）
4. **UV 从被删的旧尾巴顶点就近继承** —— 条纹花色自然延续，不用猜哪块 uv 是尾巴
5. 权重按**路径弧长参数**算：三角核在相邻骨骼间平滑混合（又平滑又不可能串味）

新尾巴路径刻意**向 +X 侧弯**（游戏机位在 +X 侧，直直向后会被身体挡住看不见）。

### 删除半径的取舍（三个档位实测）
| 半径 | 删除量 | 结果 |
|---|---|---|
| 0.075 | 625 顶点 | ✅ 采用：旧尾巴基本清掉、身体完整 |
| 0.096 | 960 顶点 | ❌ 连接处露出破口，且**破口不随半径增大而消失** |
| 0.126（按岛） | 1247 顶点 | ❌ 左前腿被开出洞 |

**根因**：生成式模型的尾巴与体表是**交织**的，没有可切的分界；切开连接处必然留一个
露出身体内侧的米色破口。彻底解决只能重新生成「尾巴与身体分离」的模型（会得到另一只猫）。
**已如实告知用户。**

### ⑥ 撕裂定位：隔离探针法（`probe_tear.py`）

### ⑦ 眼球定位：**视觉射线拾取**（`probe_eye_pick.py`）—— 本轮最大突破
- 贴图琥珀阈值路线**彻底失败**：虹膜线性 RGB 是 (0.41~0.55/0.24~0.37/0.17~0.30)，
  比肉眼感知灰得多；调阈值会依次混入奶油毛(g/r≈0.87)、鼻子/腮红(≈0.5~0.6)、耳廓阴影。
- **正确做法**：特写相机 + 40px 网格标尺图（`png_prep` 画网格）目视读虹膜像素 →
  `scene.ray_cast` 真实表面求交 → `center = hit + ray_dir*EYE_R`（相机正对瞳孔，眼轴≈−射线）。
- **两个大坑**：
  1. "顶点到射线线的最近距离"选点会滑到远处几何（实测打中后脑勺），必须 ray_cast；
  2. 最小二乘球面拟合不稳（两眼拟合半径 0.040~0.064 抖动、球心前后差 0.037），
     直接用固定眼半径反推。

  **旧 measure_v2b 注释里的 (0.205,0.055,0.480) 坐标系对不上这只模型**（附近 0 顶点），
  建了就是悬浮球。pixel 读数需两轮修正（标记球验证图）。

### ⑫ Cocos 白模根因（重大，推翻了之前两条结论）
逐层诊断（四档 mapCtrl 着色器内建诊断：y=uv直出 / z=定点采样 / w=贴图直出）：
1. setMaterial(mat,0) 替换 `.material=` —— **必要但不是根因**（对象侧一切正常）；
2. 贴图加载/绑定/UV **全部正常** —— w 档直出时琥珀眼/玫瑰围巾/虎斑纹完美呈现；
3. 真根因是 **toon 光照公式**：`col = mix(shadeColor, base, lit)`，主光来自窗侧（背后），
   朝镜头的面 lit≈0 → 前半身整体落入**纯色 shadeColor**，贴图模型正面的纹理被整个抹掉；
   叠加项（天光+补光+轮廓光）再把 base×1.02+... 顶到 clip —— 与 PBR 时代"78000lux 顶白"同类。
**修复（pet-toon.effect 一行）**：暗部改 `mix(shadeColor.rgb * base, base, lit)` ——
带贴图的暗部；房间部件 base=白乘法等价，**零回归**。TS 侧 lightCtrl 压到 (0.86,0.24,0.10,0.12)。
