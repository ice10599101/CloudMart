## 3D 宠物游戏原型 — 角色资产交付

**需求**：做一款 3D 宠物游戏原型（目标平台 Cocos Creator 4），风格对标腾讯 QQ宠物。
经确认：交付形态 = 3D 宠物模型资产；视觉风格 = 现代 3D 卡渲 PBR；范围 = 宠物主界面。

**版权决策**：未使用腾讯任何美术资源。从其视觉基因（大头身比约 1:1.2、大眼占头宽 1/3、
短粗四肢、清晰外描边、单主光 toon 材质）抽象出原创角色「云团团」——深墨蓝 + 奶白双色块、
云朵状呆毛、珊瑚橘短喙与脚蹼、焦糖色针织围巾、腮红。

**产物**（`concept/` 与 `model/`）：
- `concept/pet_concept_clean.png` — 去水印并做主体包围盒归一化后的角色设定图（972×972）
- `model/pet_penguin_20260922_021312.glb`（54.5 MB，含 PBR 材质）
- `model/pet_penguin_20260922_021312.fbx`（59.3 MB）
- `model/pet_penguin_obj_20260922_021312.zip`（46.5 MB，OBJ）
- `model/pet_penguin_viewer.html` — model-viewer 可交互预览
- 建模参数：混元 3D 3.1 / 图生 3D / EnablePBR / FaceCount=300000 / ResultFormat=FBX

**关键限制（重要）**：模型**无骨骼、无动画**，开箱不能走/挥手；面数 30 万远超移动端预算，
需减面到 8k–15k 并另行绑定骨骼。已向用户说明。

**Cocos 管线**：Creator 4.0 支持 FBX 2020 与 glTF 2.0，FBX/GLB 均可直接拖入。

## 猫咪宠物「奶盖」— 同管线第二批

**背景核对**：新版 QQ宠物 2026-07-27 回归（首发企鹅 / 狗狗 / 蒜头鹅），
猫咪系列 2026-09-05 上线共 6 只；美术基调为 **3D 毛茸茸**（触摸时毛发随方向摆动），
非旧版 Flash 2D 那套。目标平台 Cocos Creator 4 + cocos-cli
（`cocos build -j <项目> -p <平台>`，另有 create / import / make / run，以及
`cocos start-mcp-server` 可把项目操作暴露给 AI 代理）。

**关键教训 — 图生 3D 的姿势约束（已复用于本项目后续所有宠物）**：
第 1 版设定图让尾巴与身体在视觉上分离、前肢外张、胡须悬空 → 3D 结果**碎成多块**：
尾巴变成独立悬浮体、胡须成细棍、前肢糊成一团。
改为「正坐、四足落地、尾巴向前绕身贴体、胡须贴面绘制、轮廓饱满无孤立部件」后，
一次得到单一连通体积。
→ **规律：图生 3D 的输入图必须是连续封闭体积，禁止悬空细长结构。**

**产物**（`model/pet_cat_*`）：GLB 48.8MB / FBX 54.0MB / OBJ zip 41.2MB / 预览图 /
`pet_cat_viewer.html`。参数同上批（混元 3D 3.1 · 图生 · EnablePBR · FaceCount=300000 ·
ResultFormat=FBX）。设定图 `concept/cat_concept_clean.png`（945×945）。

**已知不足**：贴图上的眼睛比设定图偏小（"眼睛占脸宽 1/3"被压扁）；
仍无骨骼无动画；30 万面超移动端预算。企鹅「云团团」是磨毛布质感、猫是毛茸茸质感，
若要放进同一产品线需统一材质语言（企鹅需重出）。

**工具改进**：
- `tools/png_prep.py` 新增 `paint_out()` —— 先用上方背景色填平水印矩形再算包围盒，
  避免裁切矩形把水印残料带进 3D 输入。
- `tools/fetch_model.py` 改为接收 (结果JSON, 文件名前缀) 两个参数，支持多物种复用。

## 眼白改色：纯白 → 暖米黄（贴图级修复，零生成额度）

用户反馈眼睛"空洞、眼珠子外面都是白的"。定位：AI 生成的宠物**眼白是纯白**，
在浅色毛色上对比过强 → 读作空洞、发直。这是生成器的系统性问题，不是本项目个案，
所以**没有重新生成**（重跑大概率还是白的，白烧 45 点数），而是直接改反照率。

**做法**：
- 用**琥珀虹膜**（4225² 贴图里唯一的高饱和暖色区）定位眼睛 UV 岛。两市共用同一 UV 岛
  （镜像），改一次两眼都生效。
- 只对**低饱和（max-min≤40）+ 中高明度（lum 118–185）**像素染色；
  虹膜、瞳孔、毛发、围巾、铃铛全部不动。
- 混合强度按明度渐变，保留眼白自身的明暗过渡。
- 目标色 **暖米黄 #F1E2AA**（刻意低饱和）—— 高饱和黄在浅灰动物身上会读作"黄疸"。

**验证**：差异图确认 613 个采样点**全部**落在眼部邻域，**越界污染 0 像素**。

### 新增可复用工具
- `tools/atlas_eyes.py` —— 在 4096² 反照率图里靠琥珀色像素定位眼睛 UV 岛。
- `tools/eye_regrade.py` —— 定向改色 + 生成前后对照图。参数在文件头（TARGET / LUM_FLOOR / BLEND）。
- `tools/glb_repack.py` —— **把替换后的贴图写回 .glb**：重建所有 bufferView 偏移与 BIN chunk
  （每个 bufferView 4 字节对齐，满足 glTF accessor 对齐要求），改完结构无损。
- `tools/glb_inspect.py` —— 解析 GLB，导出内嵌贴图，统计面数/材质/骨骼/动画。

### 工具修复（重要）
`png_prep.write_png()` 原本用**无滤波（filter 0）**编码，4096² 贴图重编码后 30.4MB，
比原图 21.8MB 还大。改为 **Sub 滤波（type 1）** 后降到 **17.07MB**，比原始贴图更小。
**结论：自研 PNG 写出必须用 Sub 滤波，filter 0 对照片类纹理会严重膨胀。**

**产物**：`model/pet_cat_warmeye_20260922.glb` **51.63MB**（比原 GLB 55.34MB 更小）；
`pet_cat_viewer.html` 支持新/旧版本切换（原版按需懒加载）+ 曝光滑杆。

### 修正一：高光被一起染黄了（用户发现"眼睛看着是金色的"）

测量后确认是操作失误：
- 眼球高光点 `#F4F2F1` → `#F1E2AA`，**眼内最高明度 249 → 212**
- 高光是眼里唯一的中性色，也是"湿润、有神"的全部来源。它一变黄 → 虹膜金 + 眼白黄 +
  高光黄糊成一片暖色，整只眼睛读作一颗金球。
- 修正：加 `KEEP_FROM=200 / KEEP_FULL=235` **明度保护** —— 越亮染色越弱，高光完全不动。
  校验：高光保持 `#F4F3F2`，眼内最高明度回到 **249**。

### 修正二：作用范围溢到眼周毛发

原实现是"琥珀色包围盒 + 画圆"，而 `is_amber` 判据过松，把眼球外围的暖色毛发也算成虹膜，
导致圆偏大、暖色溢到眼周。改为：
- `is_amber` 收紧（sat>68 / r>118 / r-b>78）→ iris mask 变成 11226px，bbox 仅 195×197
- **沿虹膜做 4 邻域 BFS 外扩，并按到达距离渐隐**：REACH_INNER=24 满强度 →
  REACH_OUTER=54 归零 → 无硬边，不会像给虹膜描一圈黄边
- 改色像素 82,601 → **17,799**，且**只有距虹膜 54px 内的像素才可能被触及**（结构性保证）

### 可复用结论（重要）
给生成式宠物贴图做局部改色时：
1. **定位用"沿主体外扩 + 距离渐隐"，不要"画包围盒/圆"** —— 包围盒会被误检inflate。
2. **永远保护高光**。眼睛的高光一旦被染色，整只眼就"死"了。
3. 生成式资产的暖色误检很常见，阈值要按实测值定，不能凭感觉。

## 去金属感：材质级修复

用户反馈"不要有金属感"。实测定位到**三个成因，全部是生成器的默认行为**：

| 区域 | 粗糙度 G | 金属度 B |
|---|---|---|
| 全身 | 160（≈0.63，正常毛皮） | 18 |
| **眼睛** | **9（≈0.035，近镜面）** | **234** |
| 瞳孔 | **0** | **241** |

1. **眼球被标成抛光金属** —— 金属度 0.92 + 粗糙度 0.035，本质是一颗镜球。
2. **`KHR_materials_specular` 的 `specularColorFactor = [2.0,2.0,2.0]`** ——
   物理上限是 1.0，这里人为把镜面反射放大一倍 → 整只猫像刷了一层油。
3. **`metallicFactor` 缺省** —— glTF 规范里缺省值就是 **1.0**，材质根本没写这一项，
   于是贴图的金属通道被 100% 生效。

**修复（全部落在数据层，换引擎依然有效）**：
- 金属通道全图置 0
- 粗糙度加**下限 80**（≈0.31）：只影响原本就镜面的 **2.17%** 像素（眼、鼻、铃铛）；
  毛皮本来就 0.63，取 max 后不变。
  **要点：这种"加下限"而不是"按区域染色"的做法天然无接缝、也不会误伤** ——
  比按区域改更稳，凡是"只把过亮/过滑的极端值拉回合理区间"的需求都该这么做。
- `metallicFactor = 0`
- 摘掉 `KHR_materials_specular`，并**同步清理 `extensionsUsed`**
  （只删 material 里的扩展、留着声明会触发引擎校验警告 —— 第一版这里写错了，已修）

**校验**：眼睛粗糙度 9 → 81，瞳孔 0 → 80，全图金属度 0，`extensions: none`，
`extensionsUsed: none`，GLB **51.63MB → 45.11MB**（粗糙度贴图 12.08MB → 5.25MB）。

### 新增工具
`tools/material_fix.py` —— 材质级修复（金属度 / 粗糙度 / 扩展声明）。
复用 `glb_repack.py` 新拆出的 `read_glb / slice_views / write_glb / replace_image`，
两处改图（贴图替换、材质修复）共用同一个写出器，避免重复实现 bufferView 重建逻辑。

### 遗留（必须告知用户）
**材质修复只落在 GLB 里，FBX 仍带原来的金属材质。**
Cocos Creator 4 原生支持 glTF 2.0，建议走 GLB；若必须用 FBX，
需在 Cocos 里手工把 metallic 归零，或直接用 `model/cat_textures/` 下已修正的三张贴图重新接线。

**产物整理**：`model/pet_cat_final_20260922.glb`（45.11MB）为当前版本；
已删除被取代的中间产物 `pet_cat_warmeye_20260922.glb`；保留 `pet_cat_20260922_024623.glb` 作对照基准。

## 收窄眼白：三种方案失败，第四种成功（重要方法论）

用户反馈"两侧的眼白有点大"。**在贴图空间改眼白，连续踩了三个坑**，记录如下：

| 方案 | 做法 | 失败原因 |
|---|---|---|
| ① BFS 波前传播 | 从虹膜沿 BFS 外扩，每像素继承父像素颜色 | 波前父链不规则 → **放射状拉丝** |
| ② 逐角度边界延续 | 按极坐标测每个角度的虹膜边界色，沿同角度外延 | 放射纹本身高对比 → **辐条状尖刺** |
| ③ 逐角度边界半径 | 用每个角度的边界半径决定外扩量 | 该半径自身有噪声 → **锯齿边缘** |
| ④ UV 岛栅格化 | 把网格 UV 三角形栅格化取连通分量 | **失败**：该资产眼睛区域 UV 被切成大量碎片小岛，不存在干净的"眼睛岛"（新增 `tools/uv_island.py`，仍保留备用） |

**关键诊断（`lum` 剖面，沿六个方向每 8px 采样）**：
- 眼白 = **明亮**浅奶油 `#E7DCBD`~`#D9CCC8`，明度 **200–230**
- 眼窝阴影 / 眼周毛发 = `#6C615D`~`#827B7A`，明度仅 **115–170**
- → 两者只差约 35–40 明度，**阈值卡在中间必然漏**，这就是斑块的根源

**最终成功的做法（真·简单）**：
不做颜色替换（高对比替换才产生可见斑块），**只压暗眼白这条亮带**：
- 以虹膜重心为中心做径向渐晕（`rmean+34` 满强度 → `rmean+84` 归零）
- 只作用于 **lum ≥ 172 且 sat ≤ 46 且非高光** 的像素，压暗系数最大 **0.62**
- 结果：眼白退成暖色暗角，虹膜获得柔和外缘，**全程零伪影**

**教训（务必记住）**：
1. **压暗 / 去饱和这类"宽容操作"不会暴露选区误差；颜色替换会。** 选区不完美时，
   优先选前者。同样的选区用在"替换成琥珀色"上就是斑块，用在"压暗 60%"上就完全可接受。
2. **要替换颜色，必须有精确的边界（几何/UV）；靠颜色阈值找边界在生成式资产上不可靠。**
3. 生成式资产的 UV 布局可能是**高度碎片化**的，不要假设存在规整的 UV 岛。
4. 试错要有止损点。这块一共迭代 7 轮，其中前 3 轮方向就错了，应该在方案 ① 出现拉丝时
   就意识到"颜色替换需要精确边界"这个根本约束。

**遗留**：本方案降低的是眼白的**视觉权重**，眼白**面积本身没变**。
要真正减小面积，只能在 DCC 里改眼球 UV / 几何，或重出概念图。已如实告知用户。

**产物**：`model/cat_textures/baseColor_iris.png` 为当前反照率；
`pet_cat_final_20260922.glb` 45.12MB（metallic 0 / 无扩展 / 299,872 面 / 无骨骼动画）。

## 资产生产化：45MB → 2.21MB（可上线）

用户问"能把猫放进我项目里吗（社区宠物内嵌）"。前置阻塞是资产体积，
于是先把生产化流水线做完。

### 重大更正：npm **是**可用的
之前以为环境装不了包（pip 报 `No matching distribution`）。实测：
- `registry.npmjs.org` 直连返回 **HTTP 200**（node 的 https 不走 HTTPS_PROXY，直连通）
- npm 10.9.7 可用，但**必须用 Windows 路径调用**：
  `node "C:/.../node/versions/22.22.2-3/node_modules/npm/bin/npm-cli.js"`
  （传 Git-Bash 的 `/c/...` 前缀会被解析成 `d:\c\...` 而失败）
- 已装 `@gltf-transform/cli@4.5.0` 到 `C:\Users\Administrator\.workbuddy\binaries\node\workspace`
- **结论：以后不要再假设"装不了包"，npm 先试。**

### 生产化流水线（顺序很重要）
```
1. optimize  --compress false --simplify-ratio 0.04 --simplify-error 0.005 --texture-compress false
2. resize    --width 1024 --height 1024
3. resize    --pattern "*metallicRoughness*" --width 512 --height 512
4. jpeg      --formats "*" --slots "baseColorTexture" --quality 90
5. tangents
```
结果：299,872 面 → **11,994 面**；45.12MB → **2.21MB**；`validate` 零错误零警告。

### 五个坑（都会静默失败或产生错误结果）
1. **`optimize --texture-size` 不生效**（与 `--texture-compress` 绑定，设为 false 时贴图不缩）。
   贴图缩放必须单独跑 `resize`。第一版就是栽在这里：减面成功但体积只从 45MB 降到 36MB。
2. **`jpeg --formats` 默认值是 `"jpeg"`**，意思是"只转换本来就是 JPEG 的贴图" → 对 PNG 贴图完全不生效
   （体积一点不变）。必须显式 `--formats "*"`。
3. **`resize`/格式命令的 `--pattern` 按贴图 name/URI 匹配，而生成器导出的 GLB 里贴图没有 name**
   → 先用自己的 glb 工具给 image 写 `name`（normal / baseColor / metallicRoughness），pattern 才能用。
4. **先压缩后缩放会引入有损**（报 `Decoded EXT_meshopt_compression. Further compression will be lossy`）。
   顺序必须是 减面 → 缩放贴图 → 最后压缩。
5. **meshopt 在这里不值得**：只省 0.3MB，却引入 `EXT_meshopt_compression` + `KHR_mesh_quantization`
   两个扩展依赖 → 引擎兼容性风险。**已去掉，最终资产 `extensionsUsed: none`。**

### 切线（TANGENT）
`tangents` 命令会生成零长度向量 → `ACCESSOR_VECTOR3_NON_UNIT`（severity ERROR，着色器里会出 NaN）。
新增 `tools/fix_tangents.py` 修复。**注意顶点缓冲是交错的（byteStride=48）**，
偏移要用 `acc.byteOffset + i*byteStride`，不能按紧凑布局算 —— 第一版没处理 stride 直接跳过了。

### Bash 环境限制（再次踩到）
`tail` / `grep` / `head` **不存在**。管道里出现它们会导致**整条管道不执行**（命令静默失败），
非常容易被误判为"命令成功但没输出"。**不要用管道，直接跑。**

### 交付
`model/pet_cat_runtime.glb` —— 2.21MB / 11,994 面 / 无扩展 / glTF 校验干净，可直接进 Cocos。
`model/pet_cat_final_20260922.glb` —— 45MB 高模，留作对照与后续烘焙来源。
